# ML01 — Training-only preprocessing audit

## Question and acceptance

Can preprocessing be reused without learning from validation or test rows, and
can changing holdout values change training preprocessing or fitted ridge
coefficients? Acceptance requires a reusable training-fitted scaler and evidence
that holdout changes leave training preprocessing and fitted coefficients intact.
Both requirements are met.

## Method

The original inline scaling is replaced by `TrainingFittedScaler` in `lab.py`.
Its `fit` computes means and population standard deviations from the rows given
by the caller. `transform` reuses those statistics and returns a fresh floating
array. Zero standard deviations become one; selected constant columns are
centered. Selecting columns 0 and 1 leaves the experiment's column-2 intercept
unchanged. Invalid data, invalid column indices, unfitted transformation, and
feature-count mismatches raise `ValueError`.

`fit_training_model` accepts training and validation data only. Training data
fits the scaler and all ridge coefficients. Validation evaluates the unchanged
alpha grid (0, 0.1, 1, 10, 100); the minimum loss selects alpha. The final model
is fitted on training rows only. As before, every coefficient, including the
explicit constant, is regularized. Existing public function signatures and CLI
arguments remain compatible.

The audit generates the same synthetic AR(1) series as the baseline: seed 1729,
1,500 rows, unit Gaussian innovations, prescribed coefficient 0.8 before step
1200 and 0.3 afterwards. Chronological partitions have 900 training, 299
validation, and 299 test rows, with one excluded row between partitions.
After generation, only test rows are altered: feature 0 becomes `1000+10*x0`,
feature 1 becomes `-500+20*x1`, and targets become `100-7*y`; the constant stays
one. Training and validation arrays are identical between fits. We compare
fitted means/scales, transformed training rows, coefficients, alpha, and
validation losses after also transforming each holdout.

A deliberately leaky control fits the scaler on all rows before fitting ridge
on training rows at the same fixed selected alpha. It measures whether this
intervention can detect use of holdout features during preprocessing. This
control never supplies the reported predictive model. The audit repeats the
same fit deterministically; its repeats are not independent statistical samples.

## Reproduce

From the project repository using the installed Python/NumPy environment:

```powershell
python -m unittest discover -s tests -v
python lab.py --output results/latest.json
```

Measured environment: Python 3.12.3, NumPy 2.2.4, local CPU. No new dependencies
or paid APIs. Runtime, energy, and monetary cost were not benchmarked; local
hardware and installed software are assumed available. The audit adds repeated
small CPU fits and two intentionally leaky control fits.

Alpha and every validation loss are exactly unchanged under the intervention.
The training-fitted model's three coefficients are approximately
`[1.3011585210561962, 0.020385783248785323, -0.18835238093160414]`.
The leaky control responds strongly, so zero changes in the proper path are not
caused by an ineffective intervention. Predictions and scoring should respond
to changed holdout values, as observed. The altered MSE is a stress-test output
on artificial mutations, not a meaningful forecast error estimate.

The negative finding is preserved: ridge performs worse on this prescribed
shifted holdout than the training-mean predictor. Correct preprocessing does
not guarantee predictive success. Refactoring preserves the baseline numerical
behavior within floating-point precision.

All 13 unittest cases pass (four existing and nine new). New tests cover known
statistics, integer inputs, intercept preservation, constants and single rows,
input copying, frozen inference statistics, invalid inputs, and the leaky
control. Integration tests replace the public experiment's synthetic generator
with copies whose test features, targets, or both are changed; fitted state,
alpha, and validation losses remain exactly equal while holdout MSE changes.
Additional tests at seeds 7, 31, and 1729 change all nontraining features and
confirm identical training transforms and coefficients for fixed alphas
0, 1, and 100. Validation is permitted to affect alpha selection, so that
fixed-alpha test does not assert validation independence of model selection.

## Limitations and interpretation

- All data are synthetic. One prescribed shift and one main seed do not
  establish forecasting ability, novelty, or superiority over other methods.
- This is an isolation regression test for the implemented data flow, not proof
  that every conceivable pipeline or mutation is leakage-free. The scaler
  cannot determine whether rows passed to `fit` are actually training rows.
- The mutation occurs after feature/target generation; it does not simulate an
  alternative coherent AR(1) history. The constant is intentionally unchanged.
- The scaler supports finite dense matrices only. It is sensitive to outliers;
  missing values, sparse data, weights, and incremental fitting are unsupported.
- Coefficients of the two leaky models use different standardized coordinates.
  Their difference diagnoses contamination, not a raw-coordinate effect size
  or a guarantee of optimistic test scores.
- A one-row gap is appropriate only for the existing one-step labels. Repeated
  development against a fixed holdout can still overfit it; fresh confirmation
  and broader shift/seed studies remain future work.

The primary guidance for training-only fitting and scaler conventions is
documented with verified links in [REFERENCES.md](../REFERENCES.md), especially
the maintainers' [data leakage guide](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)
and [StandardScaler API](https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.StandardScaler.html).

## What the author should understand for an interview

Explain the difference between learning preprocessing statistics (`fit`) and
applying a fixed coordinate transformation (`transform`). Even unsupervised
statistics can transmit information from holdout rows. For each feature,
`z=(x-mean_train)/scale_train`; population standard deviation uses `ddof=0`.
Constant-feature handling avoids division by zero; leaving an explicit bias
column uncentered prevents it from becoming an all-zero column.

Explain the separate roles of training (statistics and coefficients), validation
(alpha selection), and test (final scoring). For a fixed alpha the ridge
solution uses only transformed training rows and training targets, so keeping
those arrays identical leaves coefficients identical. Validation can change
the selected alpha without fitting preprocessing, which is legitimate.

Be able to demonstrate the mutation test and explain why it needs a nonzero
intervention and a sensitive leaky control. Distinguish invariant learned state
from predictions and errors that depend on the holdout. Finally, explain why
scaling changes ridge's penalty geometry, why coefficients in different scaled
coordinates are not directly comparable as scientific effect sizes, and why a
clean pipeline can still lose to a simple baseline under distribution shift.
